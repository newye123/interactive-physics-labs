# 故事化 · 真互动 · 大屏课堂包 v0.2
## 调研（GitHub/网络）+ 对抗审查 + 执行方案

> 触发背景：宇航判断现有模块「还是差了点」——不是模拟不够真，而是两件事没解决：
> **① 互动只发生在老师和屏幕之间（学生还是观众）；② 没有故事性（实验没有"由头"）。**
> 本文先给证据和诊断，再给对抗审查过的执行方案。

---

## 一、诊断：差在哪（用证据说话）

### 1.1 互动深度分五层，我们卡在第 2 层

| 层级 | 学生行为 | 现状 |
|---|---|---|
| L0 观看 | 看老师演示 | 大部分公开课课件 |
| L1 跟读 | 齐答、跟老师念结论 | 一部分 |
| L2 预测 | 举手猜结果（有闸门） | ✅ 我们已做（M6 已做，实验室待升级） |
| L3 学生决策屏 | 学生点"多数派"，屏幕按学生选择走 | ✅ 部分 |
| L4 学生上台操作 | 学生上手拖线、合闸、读表 | ❌ 全是老师操作 |
| L5 小组分工产出 | 组内角色（读数员/记录员/审核员），结论归小组 | ❌ 没有 |

**目标：每节常态课 ≥ 2 个 L4 动作 + 1 个 L5 产出（任务卡落纸）。**

### 1.2 预测环节缺了最关键的两步（有硬证据）

Peer Instruction（哈佛 Mazur）的研究（Crouch & Mazur 2001，10 年数据）：按"**独立作答 → 同桌互讲 → 二次作答 → 老师揭晓**"执行，归一化学习增益**约为传统讲授的 2 倍**；且研究特别指出：**省掉"独立作答"或"同桌互讲"，效果显著变差**（Turpen & Finkelstein 2009）。

我们现在的"举手 → 点多数派 → 揭晓"只做了 1/3——少了"同桌互讲 20 秒"和"二次举手"。

### 1.3 故事性有研究支撑，但有一个反面证据必须知道

- **正面**：叙事情境学习环境（Narrative-Centered Learning Environments，Crystal Island 一系）与 2025 年 MDPI《Narrative-Driven Digital Gamification》研究：故事的价值不是"好玩"，而是充当**组织线索**——把碎片活动串成"一个任务的若干步"，并显著提升沉浸与动机；2025 年 ACM 论文《Tiangong Zhi》用叙事驱动物理游戏验证同类结论。
- **反面**：Hanus & Fox 的研究发现"纯排行榜 + 徽章"的课程，学生**动机和满意度随时间下降**，不如不游戏化。
- **推论（写进设计约束）**：做**剧情推进与档案收集**，不做班内竞赛排行榜；故事只当"为什么做这个实验"的由头，不承载新知识。

### 2.2 中文生态的空白（我们的机会）

NOBOOK / 希沃 / 101 教育 PPT 的共同形态：**逼真实验 + 老师演示**。网上能搜到的"情境教学"论文（中文）大量停留在"教师口述情境"层面。**"全班动作协议 + 情节钩子驱动仿真 + 页码级出口题"三件套，没有现成产品**——这正是 v0.2 要做的东西，也是自研在本轮调研后仍然成立的理由。

## 三、方案主体：两层补丁

### 3.1 互动层：「课堂编排器」（让全班动起来，不依赖学生设备）

一个独立小工具条（进入任何实验室页面时出现在底部，翻页笔可操作）：

- **五个键**：`1` 计时（20s/60s/2min 三档）· `2` 举手计数（少/半/多 三档大按钮）· `3` 随机点学号 · `4` 小组计分（4 组+/-）· `5` 亮任务卡
- **预测流程升级为 PI 三步**（写进每个模块的操作卡）：
  1. 「先自己想 10 秒，不许说话」→ 手势给出答案（A/B/C 手指）
  2. 「和同桌说 20 秒，为什么」→ 计时器
  3. 「再举一次手」→ 计数 → 揭晓
- **上台协议**：每节课至少 1 次"请位同学上台替我操作"（放元件/合闸/拧灯），老师只当审核员。
- **验收指标**（每节记录三个数）：全班动作次数、预测举手率、出口题正确率。

### 3.2 故事层：「校史馆亮灯工程 · 事故档案」（z 主线设定，每集 ≤ 90 秒台词）

> **主线**：学校要改造校史馆，你（全班）是电工王师傅带的实习生。每节课接一单任务；每单结尾翻开一份"事故档案"（= 本节对应的高频错误）。章末：档案柜锁着，要用四次实测数据拼出密码。

**每集固定七拍**（结构一致性 = 老师备课成本低）：

```
来电卡 → 任务卡(绑定全班动作) → 预测闸门 → 实验室执行 → 结案卡(自动填实验读数)
      → 事故档案卡(误区回放) → 出口题(教材页码)
```

**钩子机制**：剧情推进由**实验室真实事件**驱动（合闸成功、记录满 3 组、灯烧断、超量程），没做完实验不推进剧情——故事不能脱离操作。

**样例剧本（第 4 集《一排灯全灭》，对应 11.4 p68–70）**：

| 拍 | 台词/内容 | 时长 |
|---|---|---|
| 来电卡 | 王师傅：「小陈，展柜灯带装好了……刚才一合闸——」帧二：「哢。整排灭。」 | 15s |
| 任务卡① | 「先别修。两条灯带，一条串联一条并联，**哪条坏一颗会全灭**？」手势：左/右/一样 | 40s |
| 预测闸门 | 独立手势→同桌互讲 20s→二次举手→老师点"多数派" | 60s |
| 实验室执行 | 请一位同学上台，在实验室里"拧走"一颗灯（Delete），全班看结果 | 90s |
| 结案卡 | 自动填数：「拆一支路：主路电流 0.645 A→0.32 A，另一灯亮度不变」 | 20s |
| 事故档案 #4 | 「事故原因：灯带装成串联，一颗坏、整排灭。档案提示：家里的灯都是并联。」 | 20s |
| 出口题 | 教材 p69 练习第 2 题 | 3min |

**全章节映射（把故事安到已有模块上）**：

| 集 | 模块 | 任务由头 | 事故档案（误区） |
|---|---|---|---|
| 1 | 11.1 开灯一瞬间（M1） | 校史馆电灯"一按就亮"之谜 | 「电场接通 ≠ 电子跑到灯泡」 |
| 2 | 11.2 电阻（M3–M5） | 选电线：为什么铜、为什么粗 | 「电阻只跟电压电流有关」 |
| 3 | 11.3 读数训练器（M6） | 鉴定电线芯直径是否达标（卡尺/千分尺） | 「游标卡尺不估读 / 千分尺漏半刻度」 |
| 4 | 11.4 串并联（M8） | 展柜灯带接线方式鉴定 | 「串联好省电 / 家用灯是串联」 |
| 5 | 11.4 表头改造间（M9 待建） | 给馆里做一只量程合适的电压表 | 「电压表串联、电流表并联」 |
| 6 | 11.5 多用电表（M10/M11） | 测旧电池、查断线；鉴定真假电池 | 「欧姆表不换挡、测电阻带电源」 |
| 7 | 章末（M12/M13） | **档案柜逃生房**：四个证据站 → 四位数密码 | 全章误区大复盘 |

### 3.3 技术架构（全部静态文件，file:// 双击可用）

```
labs/
  stage.html            ← 课堂舞台：底部编排器 + 故事卡浮层 + 实验室 iframe
  stage/
    stage.js / stage.css
    missions/11-1.json … 11-7.json   ← 每集剧本（台词外置，老师可改）
  circuit/workbench.html            ← 现有实验室（加 ~40 行 postMessage 桥）
```

- **故事格式**（老师 5 分钟能改一行台词）：
```json
{ "id": "11-4", "cards": [
  { "t": "call",   "who": "王师傅", "line": "……哢。整排灭。", "max": 15000 },
  { "t": "mission","goal": "哪条灯带坏一颗会全灭？", "action": "全班手势投票", "watch": "bulb-removed" },
  { "t": "reveal", "autoFill": ["主路电流", "支路电流"] },
  { "t": "file",   "no": 4, "misconception": "灯带装成串联……" }
] }
```
- **实验室桥**：`postMessage` 双向——实验室向上报事件（`switch-closed / record-added / bulb-burnt / meter-overrange / fit-done`），舞台向下发命令（`loadPreset / setRheostat / deleteComp`）。
- **为什么 v1 不引入 ink/inkjs/Twine**：① 我们的叙事是"线性七拍 + 少量分支"，自研 ~150 行足够；② ink 需要编译步骤、Twine 导出 HTML 与 iframe 通信别扭；③ 台词必须"老师随手改"，JSON 比叙事脚本语言门槛低。**升级路径**：真需要复杂分支时再换 inkjs（MIT、纯 JS）。
- **降级策略**：故事卡文本直接读 JSON；若文件缺失，只显示"任务卡纯文本版"——故事层**坏了也不影响实验**。

## 四、对抗审查（红队 10 刀，每刀都留了反制）

**R1「故事是糖衣，考试不考故事」**
→ 故事只承载"动机 + 误区"，不承载新知识；每集台词总时长 ≤ 90 秒（计时器硬约束）；出口题一律来自教材页码。老师可一键"跳过剧情"直达实验。

**R2「老师没时间改台词、更没时间背剧本」**
→ 台词外置 JSON；每张卡屏幕上一眼可读（≤ 2 行）；编排器只有 5 个键；默认隐藏，不点不出现。

**R3「高中生嫌幼稚」**
→ 用"工程 + 事故调查 + 档案"的写实风，不用卡通吉祥物；语言克制（"哢。整排灭。"不是卖萌）；如果班里气氛好，允许老师把"王师傅"演成真人角色。

**R4「屏上热闹，学生还是坐着」**
→ 每张任务卡强制绑定一个**全班身体动作**（手势/举手/同桌讲/上台）；编排器记录动作计数，作为验收指标；不绑动作的任务卡不允许进入 v0.2。

**R5「编排器又是一个花架子」**
→ 只做 5 个键；键盘/翻页笔可操作；不做动画特效；老师三天不用就删掉重做。

**R6「故事和实验室两张皮」**
→ 剧情推进由实验室**真实事件**驱动（`watch` 钩子）；结案卡数字**自动从实验读数填充**，不允许手写数字糊弄。

**R7「数据不真，故事白搭」**
→ 全部数字来自现有 MNA 求解器（Node 自检 34 项 + 浏览器实测已核）；结案卡只引用 `sol.comps[*]`。

**R8「断网/旧机器」**
→ 依然是静态文件；安全模式停动画；故事层坏了实验照跑（降级纯文本）。

**R9「AI 生成剧情失控」**
→ v1 剧情全人工写死；AI 不参与课堂运行时。

**R10「做完没人用（老问题）」**
→ 用两次课内的真实复用判断：若两节课后老师仍在手动开舞台（而不是跳过），留存；否则砍。三个验收数（动作次数、举手率、出口题正确率）每节记录，不达标先修再做下一集。

## 五、执行计划（按"晚"排，每步可停）

| 阶段 | 交付 | 工作量 | 验收 |
|---|---|---|---|
| **P0** | 课堂编排器（计时/举手计数/抽学号/计分/亮卡）挂进现有实验室 | 1 晚 | 翻页笔能全操作；不点不碍事 |
| **P1** | 舞台壳 `stage.html` + 实验室 postMessage 桥 + **第 4 集《一排灯全灭》完整剧本**（11.4） | 2 晚 | 全流程无鼠标可走：来电→任务→预测→上台实验→结案（数字自动填） |
| **★ 进班试一次** | 一节真课（11.4） | — | 记录三个数：动作次数 / 举手率 / 出口题正确率；老师口述卡点 |
| **P2** | 第 3 集（11.3 电线鉴定，接 M6）+ 第 6 集（11.5 旧电池档案，接电动势内阻预置） | 2 晚 | 每集 ≤ 90 秒剧情；事故档案卡就位 |
| **P3** | 章末逃生房（四证据站→四位密码）+ 第 1/2 集快卡（各 60 秒，轻量） | 2 晚 | 打印版任务卡同步产出（无屏幕也能玩） |
| 明确不做 | 账号体系 / 3D 重装 / 排行榜 / AI 实时生成剧情 / 学生端设备方案 | — | 见第四章 R1/R3/R9 |
